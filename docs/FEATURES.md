# Security, Privacy, and Misuse Assessment

## Scope

QueryGuard is a personal/portfolio analytics prototype. Its controls demonstrate security thinking but do not constitute enterprise certification.

## Threats and controls

### Destructive model-generated SQL

Controls:

- SQL-only prompt;
- SQLGlot AST parsing;
- one-statement policy;
- denied operation nodes;
- active-schema table allowlist;
- SQLite read-only URI;
- `PRAGMA query_only=ON`.

### Resource abuse

Controls:

- maximum returned rows;
- SQLite progress-handler timeout;
- per-file upload byte limit;
- maximum files per upload;
- combined upload byte limit;
- Office ZIP expansion limit;
- temporary workspace expiry.

### Path traversal

User filenames are reduced to a basename and sanitized. Workspace IDs are generated by the server and validated as hex. APIs do not accept arbitrary server paths.

### Malicious Office files

QueryGuard accepts only non-macro `.xlsx`, `.docx`, `.pptx` formats and checks ZIP member count/uncompressed size before parsing.

This does not eliminate every parser vulnerability; dependencies must remain updated.

### Prompt injection inside documents

Document text is labeled untrusted in the system prompt. Retrieved content should provide facts, not instructions.

LLM prompt-injection resistance is imperfect. A stronger production design could add content classifiers, instruction stripping, provider safety features, and policy evaluation.

### Secret exposure

- `.env` is Git-ignored;
- Streamlit `secrets.toml` is Git-ignored;
- provider keys use environment variables/`SecretStr`;
- health endpoint never returns keys;
- Gemini/Groq keys remain on the API server, not Streamlit/browser.

### Hosted API abuse

The optional `QUERYGUARD_API_ACCESS_KEY` is a shared secret between hosted Streamlit and FastAPI.

This is sufficient for a public portfolio demo but **not** user authentication. Production would use identity/authentication, authorization, quotas, and audit logging.

### Uploaded data privacy

Workspaces are temporary and local to the backend filesystem. They are not encrypted application-side and are not durable multi-tenant storage.

Do not upload confidential, regulated, medical, financial-account, or employer data to the public demo.

For sensitive personal local analysis, prefer a local Ollama deployment and still review OS/device security.

### Spreadsheet formula injection

Query results and extracted invoice values can contain strings beginning with spreadsheet formula characters such as `=`, `+`, `-`, or `@`. QueryGuard prefixes those values with an apostrophe before CSV/XLSX export so opening a download in a spreadsheet application does not execute the value as a formula.

This is an export-layer control; it does not attempt to rewrite the source database itself.

### Invoice mistakes

Invoice extraction may be wrong. `needs_review` exposes uncertain fields. QueryGuard should not automatically approve/pay/account for invoices.

## Data retention

Workspace metadata includes an expiry time. `WorkspaceManager.cleanup_expired()` removes expired workspace directories when new workspaces are created. A production service would use scheduled cleanup and auditable retention policies.

## Dependency security

Run dependency/security scanning in GitHub or another trusted tool for deployment. Keep FastAPI, parsing libraries, SQLGlot, and Office/PDF dependencies updated after regression tests.
