# Security and misuse assessment

## Threats considered

- destructive SQL generated by the model;
- multiple statements in one response;
- unapproved table access;
- administrative SQLite statements such as ATTACH/PRAGMA;
- prompt injection inside a user question;
- long/expensive read-only queries;
- hallucinated tables/columns;
- arbitrary local database paths;
- accidental LLM/API secret commits;
- public callers consuming hosted-model quota directly through the FastAPI endpoint.

## Controls in v1.1

- SQLGlot AST policy before execution;
- one-statement rule;
- SELECT-style root allowlist;
- table allowlist built from the configured database;
- read-only SQLite URI plus `query_only` pragma;
- query progress timeout;
- returned-row cap;
- user question length validation;
- database path is server configuration, not a request parameter;
- `.env` and `.streamlit/secrets.toml` excluded by Git;
- provider API keys are read only from environment/secrets configuration;
- hosted `/query` calls can require `X-QueryGuard-Key`;
- Render can generate the QueryGuard app-to-app key instead of storing it in source;
- security rejections do not enter the model-repair path;
- `/health` exposes provider/model status but never secret values.

## Hosted-demo boundary

The shared `X-QueryGuard-Key` protects the FastAPI endpoint from direct unauthenticated use when configured. It is an app-to-app preview control, **not** a replacement for end-user authentication, authorization, rate limiting, WAF controls, or enterprise identity.

The Streamlit demo is still publicly usable by people who can access the page, so they can consume the hosted model through the intended UI. Provider free-tier quotas therefore remain an additional practical limit. A production version should add user authentication and per-user/service rate limiting.

## Known gaps

V1.1 has no end-user authentication, row-level permissions, column-level masking, tenant isolation, external rate limiter, centralized audit storage, or dedicated network security layer. Therefore it should not be connected to confidential production data or represented as a production security boundary.

The public demo uses a public sample database. Do not enter private or regulated data into hosted free-tier model providers without reviewing their current data-use terms.

## Secret handling

Never commit or paste these values into GitHub source files:

- `QUERYGUARD_GEMINI_API_KEY`
- `QUERYGUARD_GROQ_API_KEY`
- `QUERYGUARD_API_ACCESS_KEY`

Use Render environment variables and Streamlit Community Cloud secrets for hosted deployments.

## Reporting

For a real repository, use GitHub private vulnerability reporting or contact the repository owner. Do not include private credentials or confidential data in an issue.
